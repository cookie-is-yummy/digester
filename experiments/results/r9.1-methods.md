## Code

- `experiments/methods/c91t_lib.py`
  - **qi-v1 frame:** a generic prompt with two invented few-shot pairs, a strict JSON schema (deliverable kind, subject, qualities tone / looks / sound / said, creator named / described, time, specificity, drop, item_language, a weight or null per field, `direction` of schema type null). `validate_frame` checks and cuts every field in code; `plan_frame` builds the search strings in code: dense = [subject, item_language], HyDE = [item_language], BM25 = content tokens of subject + item_language + named creator, minus drop words. The raw query is in no dense or BM25 list. It still feeds the platform prior.
  - **rf-i1 refine:** the rf-v1 mechanics (top 20, candidate lines, friends never sent, id-enum schema, 3 tries, reorder) with a new system prompt. It sees the frame (wants instance / about / tutorial, subject, qualities, creator, time, item_language) and a generic 4-point rubric (instance vs about at most 1).
  - **ri-v1 detector:** fixed regexes for deliverable nouns, quality / superlative words and "top N".
- `experiments/methods/c91t_search.py`
  - Steps: `frames`, `vectors`, `refine`, `timing`, `run`, `compare`, `report`.
  - The Q8 pipeline is re-implemented with the path and plan as inputs. Its `q8` config is the reproduction gate.
  - New query vectors go to arm-only stores `r9.1-t1/qvec_{3l,te}`. facet_dev inputs are read only from `runs/rewrites/facet_dev/`.
