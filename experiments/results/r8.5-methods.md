**Code:**
- `experiments/methods/c85_lib.py`:
  - TS: `ts_weight` (w = clip((q_ig − 0.35) / (0.75 − 0.35), 0, 1)) and `fuse_weighted`. `fuse_weighted` calls `fair_fuse` exactly at w = 1 (TI) and at w = 0 (P); in between, it scales the coverage-fair te group term by w, both the real term and the imputed one.
  - Q8: `QMat`, a stand-in for `Combined.V`. It holds per-dimension int8 codes (max-abs / 127) and float32 scales. `@` computes V8 · (s ⊙ x), upcasting int8 in blocks of 8,192 rows. Indexing returns the dequantised rows.
  - QB: `BinIdx` (packbits sign codes, 128 B per item, Hamming via XOR + popcount on uint64 words, top-k with unique (distance, row) keys) and `own_lists_qb`.
  - `float_dense_top` gives the float dense top 100, used only for diagnostics.
  - `Refiner85`: rf-v1 unchanged. It reads the round-8.2, 8.3, 8.4 and 8.5 caches; the oldest response with identical inputs wins. It writes only to `cache/r8.5/rf-v1.jsonl`.
- `experiments/methods/c85_search.py`:
  - `refine`: a pre-refine pass gives each arm's own gated top 20s, and a call is paid only for inputs no cache holds (ledger purpose `c85_refine`);
  - `run --configs tfy | ts | q8,qb`: one vector mode per process, float for tfy and ts, int8 for q8 and qb;
  - `bench`: the dense-scan micro-benchmark and storage;
  - `compare`.
- It reuses round 8.4's search path (`search_one` logic), round 8.3's `TeIG`, round 8.2's `PlatformPrior`, `Refiner`, `top10_diag` and `compare`, and round 8.1's `ShapeRouter`, query loading and rewrite merging, all unchanged.

### Y8.5-TS · `ts-v1`

F(i) = RRF_O(i) + w · G_te(i), where w = clip((q_ig − 0.35) / 0.40, 0, 1). Then P's multiplier is applied, then the refine gate.
- w = 1 gives TI's fusion exactly; w = 0 gives P's exactly.
- On a w = 0 search the te index is not queried locally. The 3-small call is still made in parallel, as in TI's cost model.

### Y8.5-Q8 · `q8-v1`

- **Quantisation:** per-dimension symmetric max-abs, 127 levels. It is computed over the 121,169 index rows in 0.6–0.8 s. There is no renormalisation and no rescoring.
- **Fidelity:** the dequantised vectors have cosine 0.99995 to float (p1 and p50 on a 1-in-97 sample), with norms 0.9994–1.0008 (p1 to p99).
- **Where it is read:** every reader of the 3-large item vectors uses the int8 store: own dense lists, the PRF centroid, more-like-this, and the creator profiles in `ShapeRouter` and the prior's creator term.

**Numpy has no int8 GEMM.** The int8 scan here is about 4.6× slower than float32 because each block is upcast before the multiply. A real desktop build would use an int8 dot kernel (e.g. SQ8 in faiss / usearch, VNNI), where int8 is normally faster than float32. The Q8 rankings do not depend on the kernel: the score is defined as V8 · (s ⊙ q) in float32.

## Deviations and notes
