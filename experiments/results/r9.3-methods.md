## Code

- `experiments/methods/c93_lib.py`
  - **C1 `build_map` / `VocabMap` (pv-v1, code only).** It builds a per-user map from the user's own library: captions or titles (first 600 characters), hashtags, creator display names and handles, and collection and playlist names. Items from mutual-follow (friend) creators are left out. It uses no search log, no eval text and no te text. There are four entry types, all with fixed thresholds:
    - **acronym** ↔ phrase (initials);
    - **join / clip** ↔ phrase (a[:i] + b, or a+b+c);
    - both of these need at least 2 co-occurring items (5 for 2-letter acronyms), the phrase in at least 3 items, P(token | phrase) ≥ 0.25 and lift ≥ 10, and only the best pairing per side is kept;
    - **creator alias**: an Instagram handle → the YouTube channel with the same display name;
    - **collection name** → its top 2 terms by lift.
  - `expand` matches keys on the **raw** search. It adds at most 3 entries and at most 8 new tokens. They become extra terms in the own BM25 and te BM25 lists, scored as score(BM25 string) + 0.3 × score(extra).
- `experiments/methods/c93_search.py` has the steps `vmap`, `refine`, `run`, `compare` and `report`. It is built on `c92_search.make_env`, the Q8 pipeline.
  - **C2** keeps Q8's retrieval and gate. On a gated search it calls `c91t_lib.RefinerI` (rf-i1, gpt-5-nano, minimal reasoning) with the cached qi-v1 frame of the same search and repeat. It falls back to rf-v1 when no valid frame is cached.
- **The map is user data.** It is stored only at `data/all/r9.3/c1_vocab_map.json` (gitignored). In the product it belongs in the private vault, never in the shared store. Each run rebuilds the map and asserts that it equals the stored copy.

## Flags for the evaluator

1. **C1 barely touches its own target.** It fires on 0 of the 3 dev / facet_dev shorthand searches, and its acronym and clipping entries almost never fire. Most of its firing is broad collection-name terms (about 34 search-entries per repeat). Its biggest known_dev effect is the cross-platform creator alias: 10 searches, all on the instant path, which has no refine. Watch those for displaced targets, as with B1.
2. **C1 fires on 20% of ig_known_dev**, mostly through collection terms and phrase → joined hashtag. That set is synthetic and te-biased, so read its Δ with that in mind.
3. **C2 changes the top 10 on almost every refined search.** Its dev, facet_dev and known_dev Δs come only from the refined subset: 15 / 7 / 44 searches per repeat. Report the subset.
4. **C2's cost and latency expectations were missed.** It is +36% in cost and +2.9 s on the refined screen (p50). If it gains, the cost rule applies.
5. **Frames are reused from round 9.1** and still say "tutorial" on about 40% of refined searches. The rubric line "the right subject but the wrong kind" can push down good items on a wrong kind reading.
6. **yt_holdout is copied from Q8** in both arms. Do not score it.
