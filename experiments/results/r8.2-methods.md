## Arm definitions (as preregistered)

**Y8.2-P · `prior-p1`.** This applies to every typed search on both paths, after B8.1's fusion. It has three terms, combined in log-odds:
1. **Text guess:** e_t = logit(clip(q_t, 0.1, 0.9)), where q_t = p_ig + p_both / 2 from round 7's router platform head.
2. **Library top 20:** e_k = logit(s) − logit(π).
   - s = (n_ig + 4π) / (20 + 4), where n_ig = Instagram items in the search's own fused top 20.
   - π = the Instagram share of the whole index = **0.1555** (the user's platform split).
3. **Matched creators:** e_c = clip(logit((n_ig,c + 1) / (n_c + 2)), ±2).
   - The creators are those whose handle or name equals a 1–4-token n-gram of the query (round 8.1's creator-match rule, keeping the platform).
   - e_c = 0 when no creator matches.

z = 0.5 e_t + 0.5 e_k + 1.0 e_c and q_ig = σ(z). Each fused score is multiplied by exp(0.5 (q_g − 0.5)), with a stable re-sort.
- That is round 7's calibration form and strength, with a different platform read.
- Multipliers stay within 0.78–1.28, so this is never a filter.

**Y8.2-L · `lean-l1`.** This changes rewrite-routed typed searches only:
- H0 own lists;
- then H4 creator search when qs-v1 `creator_lookup.is` is set (`Creators7d` enriched profiles, as H5d, with no router-type trigger);
- then H1 guarded filters (qr-v1 filters → `qr_intent` → `guard_v43` → `apply(widen_only, unknown_watch)`).

It has no calibration, soft time, facet or format boost, and no te lists.

**Y8.2-F · `rf-v1`.** This changes rewrite-routed typed searches only. It makes one gpt-5-nano call per search and repeat:
- reasoning_effort minimal, strict JSON schema `{"ids": [enum]}`, max 800 completion tokens;
- input: the original query plus each non-friend item of B8.1's fused top 20, in fused order. Each item is sent as id c01…c20, platform, creator @handle (name), cleaned title / caption ≤ 200 characters, and the te-v1c summary ≤ 200 characters where present;
- all of it goes inside a `<candidates>` block that the system prompt calls untrusted third-party data.

Ordering:
- Valid unique ids come first, in the returned order, then missing ids in fused order. They refill the non-friend slots.
- Friends (`owner_relation` = mutual) are never sent and keep their exact slots.
- A failed call leaves the top 20 unchanged.

## Deviations and notes

1. **Refine latency was measured with 4 calls in flight at once.** These are network calls, so per-call seconds should be close to sequential ones. The P / L seed-0 runs overlapped with that job, which affects local CPU time only, slightly.
2. **One smoke-test refine call** (one search, repeat 1) was made before the batch to check the schema. Its response is in the cache under the same key and was reused, so nothing was paid twice and no outcome was seen. I printed only counts and tokens.
3. **P's creator term fires far more often than route-r1's creator match on `known_dev`** (163 vs 11). That is because P checks every typed search and keeps every match, while route-r1 checks only 5–8-token searches. This is the preregistered rule, unchanged.
4. **F reorders aggressively** (most of the top 20 move). That is model behaviour under the fixed prompt; nothing was tuned.
5. **`ig_known_dev` bias flag for F** (preregistered): those searches were written by a model reading caption, creator and te summary, which are the fields F shows. Any F gain there may be inflated, so weigh dev and `known_dev` more.
6. **Not seen:** no labels, no `eval_work/`, no per-search scores, no query or item text printed or written in `experiments/`.
