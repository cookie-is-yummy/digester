## Deviations and notes

1. **Refine concurrency:** I used 6 workers for the paid pass, against 4 in earlier rounds. This was not in the preregistration. It does not touch any ranking, but the live call seconds behind the refined-screen latency were measured under 6-way concurrency. They came out close to B8.5's cached nano seconds (new nano p50 1.20 vs 1.27–1.37 s), so the effect looks small.
2. **Timing comparison:** as-run local latency is lower in the arm runs than in B8.5's runs, although the pre-refine code is the same. So the two-stage tables use B8.5's per-search first screen for both arms (`tmp/r8.8_checks/q8_timing`). The as-run figures are in the run files' meta (`per_split`: `first_screen`, `refined_screen`, `refined_screen_instant` / `_rewrite`, `refine_instant` / `_rewrite`).
3. **Expectations vs outcome (not rules):**
   - FK made 906 new calls, as expected, for $0.077 against the ≈ $0.09 estimate.
   - FK's $ / 1k typed is $0.098–0.099, as expected (≈ $0.10).
   - FM cost $0.104 against ≈ $0.10.
   - FM's refine call is faster than the 1.5–3 s range I guessed (p50 1.55–1.62 s).
4. **None from the preregistration in the arm definitions.** The gates, models, prompt, schema, top 20, tries, max tokens, reasoning effort, cache rule and friend handling are all as written.
5. **Not seen:** no labels, no `eval_work/`, no per-search scores, and no query or item text printed or written in `experiments/`.
