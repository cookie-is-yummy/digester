## E1: guards that only widen (Y4.3-E1)

Everything is D4 except the guard:
- **`require` is one constraint.** If any flag in `require` lacks its word in the search text, the whole `require` is dropped. D4 kept the flags that remained, which narrowed an OR set.
- **Share words.** "shared" counts as said for shared, send, sends, sent or sending. The other flags' words are as in D3.
- **Unknown watch also widens.** On a platform without watch data (the ≥ 50% rule, as in D4), an item passes `require` when `watched` is among the flags. A window check counts any interaction when `watched` is among the wanted kinds. D4 removed `watched` from the set instead.

## E2: te lists only for items whose own text is not descriptive (Y4.3-E2)

**Rule, fixed before the run.** An item is **descriptive** if all three hold:
1. its own text kind is a **title**. This is adapter-level: the YouTube adapter's caption is the Takeout title, and the Instagram adapter's is a post caption. Product code would carry it as `platform_data.text_kind`;
2. it is sufficient under the existing rule: at least **N = 4** content words, and info class not `non_english`;
3. the title is not a placeholder: a URL, or private video, deleted video, video unavailable, untitled, untitled video, or youtube.

Only non-descriptive items keep rankable te rows. Fusion is D1's coverage-fair fusion, so an item that has a te row but is descriptive gets the stand-in score RRF_O · (1 + n_T/n_O), exactly like an item without one. Query-side te rows of more-like-this examples are kept, as in C2 and D1.

## E4: per-group own BM25 statistics (Y4.3-E4)

- The own BM25 list (typed and more-like-this) is computed per group. The group is the own text kind: title (YouTube, 101,037 items with view text) or caption (Instagram, 21,293).
- Each group has its own vocabulary, idf and mean length, with the same tokeniser, k1 and b as before.
- The groups' scores are merged into one list by score. te BM25 keeps a single shared index.

**Caution, label-free.** E4 changes the platform mix more than any other arm (next table). Raw BM25 scores from separately fitted groups are not on a common scale, so the merge-by-score step itself moves items between platforms. If E4 differs from E3, part of the difference is this scale effect, not better within-platform ordering.
