## Code

- `experiments/methods/c92_lib.py`
  - **B1 `CreatorNames`:** a name table built from the library (handle and display-name keys, normalised, at least 5 characters, not all digits, friends excluded): 52,298 keys; 135 mutual-follow creators excluded. The matcher reads 1–4-token n-grams of the raw search. Its common-word guard rejects a match when every token is in STOP, shorter than 3 characters, or appears in the text of at least 50 items from other creators. Spans are longest first and do not overlap; at most 3 creators. `item_list` orders the matched creators' items by the search's own dense score, and `add_list` adds the list at 1.0 / (60 + r + 1).
  - **B2 `parse_time` / `ItemDates` / `time_boost`:** a fixed regex vocabulary (explicit forms first; vague new / old only when nothing explicit matches; round 7's OLD_RX reused unchanged). The windows are date ranges or a month of any year. Item dates are first_seen_at plus every interaction `at`. The reference date is 2026-10-30, the latest library date. In-window items get × 1.15, followed by a stable re-sort.
  - **B3 `Frames` / `b3_additions` / `bm25_weighted`:** reads round 9.1's qi-v1 cache by A1's exact key. A new call is made only where no frame is cached, and it is written to `cache/r9.2/`. Validation is A1's `validate_frame`. The extra dense phrase is `item_language`. The extra BM25 terms are subject tokens minus STOP and minus Q8's BM25 tokens, scored as score(Q8 string) + 0.5 × score(extra) in the own and te BM25 lists.
- `experiments/methods/c92_search.py`: `frames`, `vectors`, `refine`, `run`, `compare`, `report`. It is built on `c91m_search.make_env` (the Q8 pipeline). The refine is Q8's rf-v1 (nano), read from every earlier cache; new inputs go to `cache/r9.2/rf-v1.jsonl`.

- **B1 and B2 cost nothing per search.** The only extra cost is the 6 + 10 new refine inputs that their changed top 20s caused over 3 repeats. Local p50 is unchanged at 0.16–0.17 s for both arms: each adds one table lookup per search, plus list building when it fires.
- **B3 costs far more than preregistered.** I expected about +13% (A1's figure), but A1 replaced qr-v1 with the frame call, while B3 makes both calls. The frame call (≈ $0.00013) about doubles the call cost of a rewrite-routed search, which gives +77% on all typed searches. This is a cost of the design, not a change of parameters.
  - Latency: the frame call (p50 ≈ 2.2 s) is slower than qr-v1 (≈ 1.4 s). Run in parallel, the frame call sets the rewrite-path first screen: +0.7 s at p50 and p95.
  - The added string's embedding cost (< $0.000001 per search) is not counted. B3 sends one string more than Q8.
- **Throughput:**
  - runs: 5.5–6.5 searches/s uncontended (index build 30 s; B1 / B2 / B3 tables 3.7 s);
  - refine calls: 2.36 items/s (4 workers);
  - frame calls: 1.0–1.2 items/s.

## Deviations and flags for the evaluator

1. **B3's preregistered cost expectation was wrong:** +77%, not +13% (see above). If B3 gains, the cost rule applies: it is not cheaper-equivalent.
2. **yt_holdout got 18 new qi-v1 frames.** It is not on the held-out list, and Q8's files include it. Round 9.1 had no frames for it. Do not score it.
3. **B1 fires mostly on known_dev's instant path,** which the refine never sees. Where it misfires, nothing downstream corrects it. Watch the 9 known_dev sample searches it fires on that are not creator-tagged, and the singleton-creator targets that round 8.7 displaced. B1's list is much narrower than 8.7's top-5 creators: it holds only literally named creators, and is a single creator on 90% of fired searches.
4. **B2 fires on very few searches** (12 per repeat across all sets). With n this small, no set-level Δ can reach the MDE. Report its fired subset.
5. **B3 changes q_ig** on its searches, through the own-list fusion, as A1 did. The refine gate and P's multiplier can move with it.
6. **Per-facet and per-trap cells are small** (1–30 searches). Report the MDE with every cell.
