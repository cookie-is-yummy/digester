## The combined index (C0)

**Reproduction check.** `c4_lib.Combined("youtube")` with round 3's cached rewrites and query vectors reproduces round 3's `a0_r1` exactly: 33 of 33 rankings identical, 1,000 deep.

| With BM25 view text | 21,293 | 101,037 | 122,330 |

**What C0 is:**
- **Rewrite.** qr-v1 with gpt-5-nano at minimal reasoning, unchanged (prompt date 2026-10-30). There are 3 fresh repeats over the 47 typed searches, cached, and every config reuses the same three files.
- **Dense.** text-embedding-3-small at 512 d over every item vector, max over [query + phrases + HyDE vector]. The HyDE vector is 0.3·q + 0.7·mean of the 3 hypothetical captions. Rocchio PRF takes the gated top 5.
- **BM25** over each item's view text (query + keywords). Instagram uses round 1's `full` view; YouTube uses round 3's allowed view.
- **Fusion.** RRF with k = 60, depth 1,000, over content codes.
- **More-like-this.** Example centroid (outside-library examples are embedded from their given title, as in round 3) plus BM25 on the examples' text. Examples are excluded.
- The search's own `filters` from `queries.jsonl` apply to both platforms.

**Gate.** The dense gate is a per-item property set by each platform's adapter rule: Instagram uses B3's info class `ok`; YouTube uses "has a title", as in A0. The search never asks which platform a search targets, so the run is platform-blind. Applying the Instagram info gate to YouTube titles would have dropped 76% of YouTube items from the dense leg.

**Controls.** The control runs use the same code and the same cached rewrites, over one platform's items only:
- `c0ig`: Instagram items, the 22 `ig_` searches;
- `c0yt`: YouTube items, the 33 `yt_` searches.

Each control builds its own BM25 index, so idf and average length are per platform.

**Differences from Instagram B3 (round 1), the same in C0 and `c0ig`:**
- OpenAI 3-small 512 d replaces bge-small, for both captions and HyDE.
- There is no enrichment (that is C1).
- BM25 lists only positive-score items.
- Instagram items with no caption still get BM25 text from "by @handle name", so they can be found by creator.

**Definition of "insufficient" (fixed in LOG.md Y4.1-C2 before C2 was built, from item text only, the same rule on both platforms).** An item's own text is insufficient if any of these holds:
1. **No own text:** the caption or title is empty once #tags, @mentions and URLs are removed, and there is no topical hashtag.
2. **Non-English script:** the round-1 info class is `non_english`.
3. **Too few words:** fewer than **4 content words**. Content words are:
   - distinct tokens of at least 3 letters from the caption or title, with #tags, @mentions and URLs removed, lowercased, minus `lib/common.STOP`;
   - plus distinct topical hashtags: not in `common.GENERIC`, at least 3 Latin letters, and not already a caption token.

   Creator, channel, collection and playlist names don't count.

## C3: qi-v3 intent (filters only)

**Prompt.** qi-v3 is qi-v2 with these changes:
- `era_of_topic` is removed. There is no date window for life periods without a calendar time.
- qi-v2's quoted example phrases are removed from the rules.
- The few-shots are qr-v1's two synthetic pairs plus one new synthetic pair, written for this prompt and not from any eval search.
- `platform` is added.
- Behaviour flags cover both platforms:
  - liked = like;
  - saved = Instagram save / collection or YouTube playlist;
  - shared = Instagram share_self / share_friend;
  - watched = watch.
- The behaviour order uses w = 0.8·saved + 0.3·liked + 0.6·shared + 0.1·min(watches, 6). Shared takes share_friend's contract weight.

**Platform guard (post-validation, added after the first qi-v3 outputs, before any C3 run was kept; no labels).**
- The model set `platform` in 4 of the 55 dev + yt_holdout searches per repeat. Only 1–2 of them contain any platform-ish word, and one repeat set the platform opposite to the search's platform.
- To enforce the preregistered "only when stated" rule, `guard_platform` keeps `platform` only if the search text names exactly that platform: instagram / insta / ig, or youtube / yt.
- It dropped all 4 per repeat, so **no C3 run applies a platform filter**. The raw model output is kept in the rewrite files, and each run's `meta.intent_per_search` records the drop.
- The C3 runs were rewritten with the guard. The earlier unguarded C3 files were overwritten and never scored.

**Searches whose ranking the intent changes** (of 55; the rest are unchanged):

| --- | --- | --- | --- | --- |
| r1 | 3 | 5 | 1 | 1 |

| r3 | 4 | 4 | 0 | 3 |

- Hard-filter pools range from 101 to 135,493 items.
- As in round 3, gpt-5-nano at minimal reasoning varies across repeats: 19–22 searches per repeat have any intent field set, most often `topic_free` with no filter, which has no effect.
