### Round 5 (`BRIEF-5.md`) fixed parameters, written before any Y5 run (rows Y5-F0 … Y5-F5 below)

Shared by every F arm. **Base = C0** (`r4.2/c0x_r*`: cached qr-v1 rewrites, 3-small 512 d dense with HyDE and PRF, BM25 over the view text, RRF k = 60). Every F arm is C0 plus one component; slot values come from the **qs-v1** rewrite (Y5-F1), repeat k paired with qr-v1 repeat k. More-like-this searches have no query text, so F1–F4 leave them as C0 (F0 and F5 add te lists to them as D1 does). Calls: OpenAI only, through `lib/ai.py`, every call cached in `$DIGESTER_DATA/cache/r5/`.

**qs-v1 slots** (gpt-5-nano, minimal reasoning, strict JSON schema; prompt in `methods/c5_rewrite.py`; few-shots are four invented searches, none taken from or written after reading an eval search):
- `topic`: `phrases` (1–3 content descriptions; include the stated format, never tone / request / creator-lookup / behaviour words), `terms` (literal words), `expansions` (other words the person may mean);
- `format`: `value` ∈ {tutorial, review, reaction, compilation, list, clip, vlog, explainer, skit_meme, music_performance, recipe, interview_podcast, other} or null, `terms` (the person's words), `expansions` (title words for that format);
- `tone`: `values` ⊆ {funny, cute_wholesome, serious, motivational, calm, intense, nostalgic, emotional, informative} (0–2), `terms`;
- `creator_lookup`: `is` (bool), `description`;
- `request_words`, `behaviour_time` (lists); `hypothetical_captions` (3).

**F3 boost:** only the top 300 of the base fused list are touched. A slot is active when `format.value` is set and not `other`, or `tone.values` is non-empty; the tone slot matches if any of its values matches. score′(i) = RRF(i) + **0.008** · m(i), m(i) = matched active slots / active slots ∈ {0, ½, 1}. 0.008 ≈ half of a rank-1 RRF vote (1/61 = 0.0164). No active slot → C0 exactly.

**F2 creator search:** creator = an item's `owner_handle` (else `owner_name`), lowercased, namespaced by the adapter's platform field (identity only; nothing branches on it); items with neither have no creator. Profile vector = normalised mean of every member item's own 3-small vector and te vector. Profile text (BM25, same tokeniser) = name, handle, word-split handle, top 15 te topics, top 3 te kinds, top 5 te vibes, top 10 non-generic hashtags, top 20 own-text content words (`c4_lib` content-word rule) over member items. Creator ranking = RRF of (i) dense: max cosine over [description, topic phrases] vs profile vectors, (ii) profile BM25 on description + topic terms + expansions, (iii) creators in order of their best item in the arm's item-level fused list (so a one-item creator is found whenever its item is). **LLM pick (pick-v1, gpt-5-nano, low reasoning):** the top 50 creators of that ranking, friends' accounts (`owner_relation` mutual) left out, shown as name, handle, item count and the profile terms; it returns up to 3 numbers (or none) of creators that fit the description; picks move to the top in pick order. Creator-item list: creators in ranking order (top 200), at most 5 items each, ordered by the item-level fused rank, unranked members after by dense cosine. Fused with the own lists by coverage-fair RRF: F(i) = RRF_O(i) + RRF_C(i) if i has a creator, else RRF_O(i) · (1 + 1/2). Fires only when qs-v1 `creator_lookup.is` is true. Ablation `f2n` (no LLM pick) is a diagnostic, not a hypothesis.

**Deviation, before any Y5 search run (label-free; from aggregate slot counts only, no query text read):** the first qs-v1 pass ($0.022, overwritten) set `format` on 32–38 of 47 typed searches per repeat, 17–18 of them `clip` (nano read plain media nouns as a format), `tone` `informative` on 6–8, and `creator_lookup` on 1. Before any run: (a) the prompt now says a plain media word alone does not state a format, format/tone `terms` must be copied from the search, and `creator_lookup` is true when the search is about one particular creator, channel or account, **named or only described**, even when the person wants that creator's items (the first wording, "finding a creator rather than an item", was narrower than BRIEF-5's "the answer is a creator"); (b) a code guard (`c5_rewrite.guard_slots`) keeps `format` only if one of its `terms` occurs literally in the search and is not a media noun (video(s), reel(s), post(s), content, clip(s) except for value `clip`, …), and `tone` only if one of its `terms` occurs literally. The model's unguarded slots stay in the rewrite files. Result of the second pass: format kept on 14–20 / 47, tone on 4–5, creator_lookup on 1–2.

**F4 checker (chk-v1, gpt-5-nano, minimal reasoning):** one call per typed search with `format.value` set or `tone.values` non-empty, over the top 20 of the base list. Each item is shown with its own caption / title (≤ 300 chars), creator name, and, when it has a te row, te summary (≤ 200 chars), kind and vibes. Friends' items are never sent (answer = unknown = ½). The model answers yes/no per item per active property. The top 20 are re-sorted by the share of "yes" (descending), ties by base rank; ranks 21+ are unchanged.
