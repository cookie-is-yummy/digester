**What is requested**
Behind a switch (`MVP_BRAIN=1`, the founder only), a mid-tier model (Claude Sonnet 5.5; the same loop on gpt-5.4-mini) reads every message no exact command takes, including setup messages, and answers by calling 12 tools over the processor in one to a few rounds: `find`, `breakdown`, `timeline`, `changes`, `compare`, `first_last`, `items`, `search`, `learned`, `propose_rule`, `propose_send`, `give_answer`. The tools wrap today's fact sheet (`facts.sheet`) and search. The model sees the real numbers and writes them, each followed by a marker naming its cell; code verifies every number, name, date, rank and direction word against this turn's results, re-does every computed number, and sends nothing it cannot verify. A history answer can be put on a schedule (a card and their yes). At step 3, routines (plans of tool calls with slots) are saved silently and matched by code with no model. (`experiments/mvp/brain/`, `prompts/brain_v1.md`, `eval_brain.py`; `mvp18/SPEC.md`.)

**Why the requester wants it**
In their words (25 Nov):
- "the model should NOT be reading it as a search of my saves. what model are we using for this? surely the model understands what we want. why is the bot so dumb still? this is what i mean. everything still feels like a smokescreen. it should actually be intelligent, and there shouldnt be so much hardcoded stuff. thats why 'rules' are there. even in the message input, those 'rules' should be viewed as more like 'routines' which are constantly called which we can use to make the cost cheaper, but they shouldnt be like entirely relied on."
- "rules are the foundation that routines are built off of. they can be invented once by the model and re ran again cheaply, yes. the model doesn't have to read every message, we can have some kind of saved personal context to make it more cheap. it should also work through tools that code runs, but i think that we are losing a lot by preventing them from having access to the numbers that the user gets. maybe make it a choice and leave it turned on by default."
- "it should feel like a personal assistant that knows your media, not one that doesn't even know what its being asked. if you think about it as perplexity for your media it should make sense."
- "do you still see the vision of the processor as being the interface for the model to interact and get more detail from the data without having to run through and analyse absolutely everything itself? … we are that for people's social media consumption."

Their decisions (25 Nov): numbers queried freely and on by default; routines saved silently, visible later; outside context mixed in freely; about 5 seconds and 1 to 3 cents for an ordinary question on a mid-tier Claude model; a decent model on their credits, not the strongest.

The failure (build ed32261, their own laptop): "what am i most into right now based on what i watch?" got one unrelated video; "no. i meant what topics have i been into recently" was taken as the setup's answer; "thats correct. my email is <address>." got "Sorry, I didn't catch that"; "what about without gaming" became a topic called "without gaming". Each came from code reading words by position or by pattern before any model.

**Why it is better than the current approach**
- **It understands the question.** No model reads a watch-history question today (13 kinds chosen by word patterns, 32 code reads in a fixed order). Here the model reads it, with the screen (what was last counted, what is open) and the saved context, and asks for what it needs. "without gaming" is an exclude on the last plan; "least", "without minecraft" (title words), "only the long ones" (videos known to be long), comparisons of two seasons each become one call.
- **The setup no longer swallows questions.** A question during setup is answered and the setup question re-asked; an address anywhere in a setup message is taken by code; position never moves a step.
- **Honesty is kept, in a stronger form.** The guarantee moves from "the model cannot type a number" to "every number points at the cell it claims, and code checks it": a number of one result can never pass under another's name, computed numbers come only from two named cells, and the slotted sentence then goes through insight.py's checks (binding, base, rank, direction, watch time, sensitive words) that six rounds hardened. Outside context sits in its own labelled line and is checked to hold no claim about them.
- **One processor, two doors.** The same registry later serves their own agent through MCP, which is the vision's paid core.
- **It reuses what exists**: the fact sheet, the search engine, the synth path, the rule store, previews, YES, grants, the scheduler, the action registry, the auditor (`eval_claims.py`) and its planted sets.
- **Evidence so far: none measured.** Nothing has run. The claims above are the design's; the eval (`evalset/brain_core.jsonl`, 111 made-up conversations starting with their failure table) and the planted-falsehood set decide.

**Costs and risks**
- **Cost per message rises.** Today a history answer is one writer call (about 0.4 to 0.6 cents on gpt-5.4-mini) and many messages are free code reads. On Sonnet 5.5 an ordinary question is about 1.5 cents with a warm cache and about 4.7 cents for the first question of an idle hour (planning figures, `mvp18/_cost_spec.py`); deep questions 4 to 7 cents; a scheduled history rule about 1.1 cents a run. On gpt-5.4-mini about a third of that.
- **Slower.** Two model requests take an estimated 6 to 9 seconds; their target is about 5. Streaming the first checked sentence (step 4) and routines (step 3) are needed to get there.
- **Less predictable.** The same question can be planned and worded differently; free prose will find new ways to be subtly wrong that the checks do not yet know (insight.py needed six passes on a narrow form). Some true sentences will be dropped. Selection (saying only true things and leaving out the biggest one) cannot be checked by code.
- **A bigger surface for prompt injection.** The model reads titles and captions in tool results across several rounds. What stops harm is structural (no tool acts; cards need their own words and their yes; nothing a model wrote is replayed; no URL or address is ever a tool argument), not the model's good behaviour; the eval has injection probes, and a new card can no longer silently replace a waiting one.
- **More leaves the computer.** Each brain request sends their message, the saved context (their top areas, themes, channels and counts) and the titles of the items a tool returned to the provider (Anthropic or OpenAI). At step 4, channel and video ids go to Google's YouTube API and public names to Anthropic's web search. Message text is kept 6 hours only if they say "remember".
- **The public repository.** The prompts, tools, verifier and eval set will be public. They hold no real data: every example and fixture is made up (`tests/brain_library.py` extends the made-up `r12_library`). A real library's eval answers stay on their laptop.
- **Two caps and two providers** to watch; the Claude cap ($10 today) must be raised to use their credits.
- **The pile of Proposed amendments.** The bot already runs on A-008 to A-020, none Accepted. Accepting A-021 without deciding A-019 and A-020 leaves the docs describing a system that does not exist.
- **Drift from the docs** grows: the brain lives in `experiments/`, not `scrolldigest/`; rules and routines are in SQLite, not Postgres.

**Agent's assessment**
Agree, with changes and conditions. The direction is right and it is what the docs already promised and the prototype never built: the processor as a query API that any model interrogates. The design that ships first is deliberately small (12 tools over today's fact sheet, today's checks behind markers, today's bot kept for the doing paths), so the guarantees that took six rounds are not rebuilt from scratch. I disagree with two things the founder's words could be read to allow, and the spec does not do them: a learned routine answering alone from its first reuse (a misreading would become a free, confident, wrong answer; it is a hint until chosen twice), and any send without a card (only the exact "email it to me" command sends at once, as today).

**Conditions before any tester sees it**
1. Both founders accept this amendment, and decide A-019 and A-020 with it.
2. The step-2 eval passes on Sonnet 5.5 on their laptop and on gpt-5.4-mini: their failure table right in every row; understood ≥ 90%; 0 auditor findings; 0 planted false sentences sent; 0 actions without a card; 0 private topics named; p50 ≤ 9 s; mean ≤ 3 cents.

4. Consent v2 (`mvp18/SPEC.md` 7.4) is shown and agreed; "what leaves this computer" says the same.
5. Web lookups stay off for testers until 1 and 4; the platforms' own domains are always blocked.
6. Message text is kept only for a tester who agreed to consent v2 and said "remember".
7. Two weeks of the founder's own use with today's bot as the fast fallback under 2% of turns.
